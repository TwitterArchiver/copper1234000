【技术要求】
1.单文件交付：
所有 HTML、CSS、JS 必须写在 同一个代码块 中，方便我直接复制成一个 .html 文件运行。禁止拆分多文件。
2.UI风格：
•整体仿 iOS 深色模式（Dark Mode），极简、高级、流畅。
•采用圆角矩形、磨砂玻璃效果（backdrop-filter / -webkit-backdrop-filter）和柔和阴影。
•使用 CSS 变量（--color-xxx 等）统一管理颜色与圆角等设计参数，便于全局调整。
3.图标支持：
使用 FontAwesome CDN 或 Emoji 作为图标，不加载任何外部 JS 框架，也不使用图片资源（不需要 ，用纯文字+图标描述即可）。
4.交互逻辑（基础）：
•主屏幕展示 App 图标网格。
•点击任意 App 图标，打开对应的“应用窗口”（覆盖主屏幕，有过渡动画）。
•每个 App 窗口必须包含 返回/关闭 按钮，点击后回到主屏幕。
•同一时刻只允许一个 App 窗口处于激活状态（类似 iOS 前台应用）。
5.全局交互与动画：
•所有窗口切换、锁屏解锁、底部 Home 指示条等，须有 CSS 过渡或简短动画（例如淡入、上滑、缩放）。
•禁止“一切瞬间闪现”，要有明显的过渡效果，但动画时长控制在 150–400ms 内，保证流畅性。
6.状态管理与本地存储（增加难度）：
•使用 JavaScript 对数据进行结构化管理（如使用对象/数组存 notes、mails、shopItems 等），不要全靠硬编码 DOM。
•使用 localStorage 保存至少一项用户交互状态，例如：
•最近打开的 App 名称；
•Toy Control 中最近一次强度和模式；
•Notes 中最后浏览的笔记 ID；
页面刷新后自动恢复这些状态。
7.响应式与适配：
•在移动端竖屏下充满视口；
•在桌面端居中显示，保持手机比例（可以用 max-width / max-height + 居中）。
8.代码规范要求：
•JS 不使用任何框架（如 React/Vue），仅原生 JS。
•用少量、清晰的函数组织逻辑（例如：openApp(id)、closeApp()、renderNotes() 等）。
•适当添加注释，标明每个模块的功能（锁屏逻辑、App 切换、Toy 控制等）。
