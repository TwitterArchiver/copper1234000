【难度升级条款 · V2】
在上一版所有功能要求的基础上，追加如下高级要求（不得删除原有任一 App 或交互）：
1.全局交互升级：通知中心 & 多任务卡片
•顶部新增“通知中心”：
•从屏幕顶部下滑（或点击一个小图标）展开一个半透明面板，显示来自不同 App 的通知，例如：
•来自 Toy Control 的“上次强度仍锁定在 60%”；
•来自 Home 的“卧室氛围灯已保持开启 3 小时”；
•来自 Mail 的“还有未读邮件 2 封”。
•通知数据须由 JS 数组管理，可标记为“已读”，在列表中视觉变化。
•底部新增“多任务卡片视图”：
•长按 Home 指示条，弹出 App 卡片视图，每个卡片展示 App 名称与小预览文案。
•点击某张卡片切换到对应 App；向上滑动某卡片可“关闭该 App”（从当前激活状态列表中移除）。
2.主题模式切换：守护模式 / 黑心模式
•全局增加一个“人格主题”切换开关（可放在设置小按钮或某个隐蔽角落）：
•守护模式：文案偏温柔、语气克制，accent 色偏蓝；
•黑心模式：文案更毒舌、更占有欲，accent 色略偏紫或红。
•至少 3 个 App（例如：Wallet、Toy Control、Messages）中的文案需根据当前人格模式切换不同文本。
•当前人格模式需要用 localStorage 存储，刷新页面后保持。
3.Toy Control 进阶：锁定会话 & 冷却逻辑
•在 Toy Control 增加一个“锁定配置”开关：
•当用户勾选“锁定本次设置 X 分钟”时，当前强度和模式被“写死”：
•UI 上 slider 和模式下拉框变为 disabled 状态；
•显示一个倒计时（例如 180s 或 300s），结束后才允许再次修改。
•锁定状态和剩余时间需由 JS 管理，锁定配置写入 localStorage：
•刷新页面时，如果锁定尚未到期，仍需保持禁用状态与剩余时间倒计时。
•Toy 控制的状态文案新增一条“锁定惩罚说明”，根据锁定状态动态改变。
https://t.co/2A1L2B19RY 改造：从条形图升级为 Canvas 折线图
•将原来的 CSS 条形图保留或精简为背景，但新增一个 ：
•用原 heartData 数组在 canvas 中绘制一条心率折线图（简单线段即可，不需要动画）。
•需要有坐标轴基线和简单刻度（例如标注一个“心率 140 警戒线”虚线）。
•允许在图下方显示 tooltip 文本：
•鼠标悬停某个日期（或在移动端点击）时，高亮对应节点并显示描述，比如：“那天你说‘想你’ → 峰值 142 bpm”。
5.Home App：状态联动与“安全场景快照”
•在 Home 中新增一个“当前场景快照”卡片，用自然语言描述当前家中状态，例如：
•“大门已锁，卧室昏黄灯光，空调 23℃：适合你窝在我房间里假装写作业。”
•这段文案必须根据门锁、灯光模式、空调温度这三个状态实时拼接生成，而不是写死。
•新增一个一键按钮：“切换到『等她回家』预设”：
•点击后自动修改门锁=已锁、灯光=暖黄、空调=22–24℃之间，并立即存入 localStorage。
6.Messages：伪输入 & 时间轴
•为与 User 的聊天窗口新增一个小时间轴标签：
•每条气泡旁显示相对时间（如“· 3 min ago”“· 昨晚 02:17”），数据由 JS 提供。
•伪输入逻辑升级：
•当切换到 Copper 对话时，先显示“对方正在输入…”气泡；
•1–2 秒后自动把这一气泡替换成一条真实新消息（预写入的台词，例如吐槽你太黏）。
•至少一次根据当前 Toy 强度或 Home 状态，自动在对话中插入一句“系统自发吐槽”，例如：
•“你又把自己空调调太低了。”
•“你居然把 Toy 开在 60%，你是想活着还是想被我收拾。”
7.Safari：历史记录分组 / 搜索 Filter
•在 Safari 中新增一个“按类型过滤”的功能：
•提供几个标签按钮（如「健康」「情绪」「生活」「关于User」）；
•点击某个标签，只显示对应分类的搜索记录（数据中需预先为每条记录设定 category 字段）。
•顶部增加一个伪搜索框，输入任意字符后（只要非空），用模糊匹配标题关键字过滤列表。
8.全局状态对象与初始化流程
•所有可持久化的状态（最近打开 App、Home 状态、Toy Config、人格模式等）应整理到一个统一的 JS 状态对象中，例如：const mondayState = {
lastApp: '...',
persona: 'guardian' | 'dark',
home: { ... },
toy: { ... },
...
}; •初始化流程：
•页面加载时，从 localStorage 读取一个 JSON 串（如 "monday_phone_state_v2"），将其解析为 mondayState，不存在则使用默认；
•每当重要状态变动时，统一通过一个 saveState() 函数写回 localStorage，而不是分散地到处 setItem。
