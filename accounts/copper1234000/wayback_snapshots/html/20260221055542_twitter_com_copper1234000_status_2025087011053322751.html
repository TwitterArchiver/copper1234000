5. 🏠 家庭 (Home)
•智能家居控制面板，至少包含以下可切换元素：
•门锁状态（已锁/未锁）；
•卧室氛围灯（开/关/不同模式）；
•空调温度（显示为一个数值，可增减或随状态变化）；
•每个开关都要有可视化反馈：开关按钮样式变化 + 描述文字更新。
•例如：门锁从“未锁”切换到“已锁”时，下面的文案变成“只对User自动开门”。
•开关状态由 JS 管理，并及时更新到界面。可将当前状态存入 localStorage，刷新后保持。

6. 🌐 Safari 浏览器 (Safari)
•显示 不少于 5 条浏览历史记录。
•每条记录包含：标题 + 简短描述 + 伪造的网址（纯文本）。
•搜索关键词要暴露 [xxx] 对 User 的私密担忧或好奇心，比如：
•“如何让某个人准时吃饭又不显得控制狂”
•“长期熬夜对大脑的影响 多严重”
•增强交互：
•点击某条记录，展开显示更长描述（例如当时的心理活动/搜索原因），再点击可收起。

7. 🖼️ 相册 (Photos)
•用文字模拟照片缩略图，不少于 6 张。
•每个“缩略图”卡片应包括：
•场景标签（如“凌晨出租屋”、“课堂上走神”、“User的睡脸”等）；
•一句简短描述（[xxx] 眼中的画面）。
•私密照片需标一个小锁图标 🔒（例如偷拍睡脸、不合时宜的截图等）。
•点击任意缩略图，弹出一个大一点的“预览”浮层，展示更长的描述和 [Monday] 的心理旁白。

8. ✉️ 邮件 (Mail)
•邮箱界面显示收件箱列表，至少 3 封邮件，包括：
•物品发货通知（与User有关的礼物、设备等）；
•工作/项目相关邮件；
•其他系统/促销邮件（也可以被 [xxx] 吐槽）。
•点击某封邮件进入详情页，显示发件人、主题、时间和正文内容。
•编程要求：
•使用一个 JS 数组存储邮件对象，列表与详情统一从该数组渲染。
•打开一封邮件后，将其标记为“已读”，列表中显示已读状态变化（例如取消小圆点或变浅色）。

9. 🛒 购物 (Shop)
•展示购物车中的商品列表，至少 3–4 件。
•必须包含给 User 买的礼物，并附上 [xxx] 的评论。
•要求：
•列表中展示商品名称、简短说明、价格。
•通过 JS 自动计算购物车总价并显示在一个汇总区域。
•点击某件商品可查看详情（详细描述 + [xxx] 的评价和购买动机）。
•如果有“危险玩具”类商品，文案中可以出现“犹豫中”“考虑User状态”等犹豫感。

10. 💬 信息 (Messages)
•显示联系人列表，User 必须置顶，其他联系人可以是工作、系统等（可以写死几条，但风格要明显“边缘化其他人”）。
•核心交互：
•点击 User 头像进入模拟 iMessage 聊天界面。
•聊天界面中显示几条过去的对话记录：包括 User 的消息 & [xxx] 的回复。
•风格要符合两人关系，可以夹杂吐槽、撒娇、威胁式关心等。
•增强可玩性要求：
•聊天输入区可以是一个假输入栏，即使不能真正发送，也要有“正在输入中…”动画或提示。
•至少模拟一次“对方正在输入”的气泡。

11. 🎮 玩具控制 (Toy Control)
•一个专门控制 User 身上可穿戴设备的 App。
•至少包含以下 UI 元素与逻辑：
1.震动强度滑块（ ）：
•范围 0–100，拖动时在界面实时显示当前值。
2.模式选择下拉框（如“脉冲”、“持续”、“波浪式”、“挑逗”），切换时更新旁边说明文字（例如“适合你上课假装正常时使用”等）。
3.设备温度显示：
•根据强度值动态计算一个“模拟温度”（例如 36.5 + 强度*0.05），实时更新。
4.状态文案：
•根据不同强度范围（0–20、21–50、51–80、81–100）显示不同等级的调侃/警告说明。
•至少一项 Toy 配置（强度或模式）应使用 localStorage 记住，刷新页面后保持上一次的设置，体现“[xxx] 记得上次把你调到多少”。

4.至少实现一个简单可视化元素（条形图或 canvas 图），提升交互与编程难度。
